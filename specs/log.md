# Mapsift decision log

> **What this is.** A grep-able derived index of foundation versions and closed decisions. It is **not a source
> of truth.** The foundation's section 15 changelog is the authority for version history, and the document named
> in each line is the authority for that decision; this file only mirrors them in flat, greppable lines so a
> version or a decision can be found without reading a full changelog. If this file and the foundation disagree,
> the foundation wins and this file is the one to fix.
>
> **Format.** One line per entry: `## [YYYY-MM-DD] <type> | <one-line description>`, where `<type>` is
> `version` (a foundation version bump, mirrored from section 15) or `decision` (a decision closed in a derived
> document that did not bump the foundation). Grep `version` for the release history, `decision` for closed
> calls that are not in the changelog.

## [2026-07-31] version | v0.14 — the ratified database major moves from PostgreSQL 16 to 18. The request was to pin "the LTS version" and the premise is false: PostgreSQL designates no long-term-support version, supporting every major for five years from initial release, shipping a major yearly and a minor quarterly, and recommending you always run the current minor. So the pick is by remaining runway, roughly two years on 16 against roughly four on 18, and a closed-scope product built to completion and then run for years gains nothing from ratifying a half-spent major. ## [2026-07-31] version | v0.15 — performance is engineered, and the established technique is researched before an implementation is settled for, on the same discipline the external-dependency rule applies to versions. Two classes treated differently: structural performance is free at design time and therefore not optional (the index the query needs, the batch that replaces a loop of round trips, the critical section held for one statement instead of one transaction, the payload that crosses a boundary once), and skipping one is a defect with a performance symptom; complexity-adding optimisation is bought with a measurement and never a hunch, generalising the tiling gate of section 6. ## [2026-07-31] decision | ADR-0004 accepted: the sync ordering strategy is the per-project version, allocated inside the flush transaction so version order is commit order by construction. Chosen on FAILURE MODE rather than throughput: its contention is local, proportional and diagnosable, while the transaction-id watermark fails non-locally twice (any unrelated writing transaction stops the feed for every user, measured at a full 4 s stall; and its cursor is bound to the physical identity of the cluster, so a logical restore silently invalidates every offline client's cursor, which matters because Mapsift's cursor lives on field devices for weeks). Row-versioning with a client view record was eliminated on read cost (2,615 rows scanned per poll at a 5,000 backlog, halving write throughput). Delivers the SP-1 exit — `specs/adr/0004-sync-ordering-strategy.md`.
## [2026-07-31] decision | Two engineering rules are part of the ADR-0004 decision rather than optimisations to add later, because serialisation is caused by how long the lock is held rather than by the number of writers: allocate the whole version range in ONE statement per flush, and take the allocation LAST, so validation, dedup, contiguity, feature versions and the conflict rule all run outside the critical section. Measured with ten people editing while a client flushes 3,000 operations: worst interactive save falls from 782 ms to 40 ms and the flush itself gets four times faster. LATE matters more as pushes get heavier, since the critical section stops growing with them.

## [2026-08-01] decision | **`geodesic_area_unsigned` is a trap and the test caught it before any code depended on it.** "Unsigned" does not mean the absolute value of the signed area: it means the area the ring encloses UNDER ITS OWN ORIENTATION, and a clockwise ring on a closed surface encloses the rest of the planet. Measured on a one-degree square: 1.23e10 square metres counter-clockwise against 5.10e14 clockwise, which is the surface of the Earth minus the square. In a product that computes legally consequential areas, a parcel whose ring happens to be reversed would have reported a number that is enormous, wrong, and entirely plausible on a screen. The correct call is `geodesic_area_signed().abs()`, and the regression test now pins the specific failure mode rather than only asserting equality.
